# RAG NoteBook — 第二阶段开发计划

> 本文档基于 MVP 已完成的前提，规划 P1 增强功能与 P2 AI 深度集成的实施方案。

## 1. 当前状态回顾

MVP 阶段（第 0-11 步）已完成全部核心链路：用户认证、笔记管理、知识库 RAG、AI 对话、Dashboard、用户资料、以及 UX 收尾（错误处理/骨架屏/空状态/确认对话框）。

### 遗留问题（MVP 阶段需在进入 P1 前修复）

在开始新功能之前，有几个 MVP 阶段的设计细节需要确认：

- **Note 模型缺少 embedding 字段**：当前 `prisma/schema.prisma` 中 Note 模型没有 `embedding` 列，而迁移 SQL 中通过 `ALTER TABLE` 添加了该字段。P1 的语义搜索功能依赖此字段，需确认迁移是否已执行，或统一在 Schema 中声明。
- **30 天自动清理机制**：需求文档提到回收站的笔记 30 天自动清理，但 MVP 实施计划中没有明确这一步的实现方式（定时任务或 cron job），需要在 P1 阶段补齐。
- **向量索引创建**：MVP 阶段 IVFFlat 向量索引被注释掉（需有数据后才能创建），当知识库积累一定数据后应创建索引以提升检索性能。

## 2. P1 阶段 — 增强功能（建议 2-3 周）

P1 的目标是让笔记和知识库"更智能"——通过 AI 自动标注、语义检索、以及关联推荐，让知识不再沉没。

### 第 12 步：AI 自动标签 + 自动分类

**目标：** 笔记保存后，LLM 异步生成 2-5 个标签和自动判断分类。

#### 12.1 自动标签/分类服务

**新增文件：** `src/lib/ai/auto-tag.ts`

核心逻辑：
- 笔记保存后（API 层 POST/PUT），异步触发自动标签任务
- 调用 DashScope chatModel，使用 `generateObject` 返回结构化结果
- Prompt 设计：输入笔记标题+内容前 1000 字符，输出 `{ tags: string[], category: NoteCategory }`
- 使用 zod schema 约束输出格式：tags 为 2-5 个字符串的数组，category 为枚举值
- 写入数据库：将生成的 tags 合并到笔记的 tags 字段（去重），category 仅在用户未手动设置时覆盖

#### 12.2 API 集成

**修改文件：** `src/app/api/notes/[id]/route.ts`、`src/app/api/notes/route.ts`

- 在 POST（创建）和 PUT（更新）处理中，保存完笔记后异步调用自动标签服务
- 使用 Promise 不阻塞响应返回（先返回保存结果，标签生成在后台完成）
- 可选：添加一个 `?autoTag=true` 查询参数，允许前端控制是否触发自动标签

#### 12.3 前端适配

- 笔记编辑页添加"AI 生成标签"按钮（手动触发入口）
- 标签编辑区域显示加载状态（"AI 正在生成标签..."）
- 分类选择器增加"自动"选项

**产出文件：**
- `src/lib/ai/auto-tag.ts`（新增）
- `src/app/api/notes/[id]/route.ts`（修改）
- `src/app/api/notes/route.ts`（修改）

### 第 13 步：笔记语义搜索

**目标：** 基于向量的笔记内容语义检索，作为关键词搜索的补充。

#### 13.1 笔记向量化

**前提：** 确认 Note 表的 `embedding` 列已存在（来自迁移 SQL）。

**修改文件：** `src/lib/rag/vectorize.ts`（扩展）

- 新增 `vectorizeNote(noteId, userId, content)` 函数
- 在笔记保存后异步触发向量化（与自动标签并行执行）
- 向量化结果通过 `$executeRaw` 写入 Note 的 embedding 字段

#### 13.2 语义搜索 API

**修改文件：** `src/app/api/notes/route.ts`

- 新增查询参数 `searchMode=keyword|semantic|hybrid`（默认 keyword 保持兼容）
- `semantic` 模式：将搜索词向量化后通过 pgvector cosine similarity 查询
- `hybrid` 模式：同时执行关键词搜索和语义搜索，通过 RRF 融合排序
- 返回结果中标注匹配方式（`matchType: "keyword" | "semantic"`）

#### 13.3 前端搜索增强

**修改文件：** `src/components/notes/note-search.tsx`

- 搜索框旁添加搜索模式切换（关键词 / 语义 / 混合）
- 语义搜索时显示搜索模式标识

**产出文件：**
- `src/lib/rag/vectorize.ts`（修改：新增笔记向量化函数）
- `src/app/api/notes/route.ts`（修改：扩展搜索参数）
- `src/components/notes/note-search.tsx`（修改：搜索模式切换）
- `prisma/migrations/`（可能新增迁移：确认 embedding 字段）

## 3. P2 阶段 — AI 深度集成（建议 3-4 周）

P2 的目标是将 AI 能力从"辅助检索"提升到"主动创作"——让 AI 成为用户的写作伙伴。

### 第 18 步：AI 写作助手

**目标：** 在笔记编辑器内提供摘要、续写、扩写三种 AI 辅助能力。

#### 18.1 写作辅助 API

**新增文件：** `src/app/api/ai/writing/route.ts`

统一端点，通过 `action` 字段区分操作类型：

```
POST /api/ai/writing
{
  "action": "summarize" | "continue" | "expand",
  "content": "当前笔记内容",
  "cursorPosition": 120,    // 续写/扩写时需要
  "selectedText": "..."      // 扩写时可选
}
```

- `summarize`：对整篇笔记生成 200 字以内的摘要，流式输出
- `continue`：从光标位置继续写作，基于光标前的上下文生成后续内容
- `expand`：对选中的段落进行扩展，丰富细节和论述

三种操作均使用 `streamText` 流式返回。

#### 18.2 编辑器集成

**新增文件：** `src/components/notes/ai-toolbar.tsx`

- 在 Milkdown 编辑器工具栏下方添加 AI 操作浮动菜单
- 三个按钮：摘要（Summarize icon）、续写（PenLine icon）、扩写（Expand icon）
- 续写/扩写：选中编辑器中的文本后激活
- AI 输出区域：在编辑器下方展示流式生成的文本
- "插入"按钮：将 AI 生成内容插入到编辑器光标位置
- "替换"按钮：将 AI 生成内容替换选中文本

**修改文件：** `src/app/(main)/notes/[id]/page.tsx`

- 集成 AI 工具栏组件

**产出文件：**
- `src/app/api/ai/writing/route.ts`（新增）

### 第 19 步：Agent 对话

**目标：** 将基础 RAG 对话升级为 Agent 对话，支持工具调用。

#### 19.1 Agent 工具定义

**新增文件：** `src/lib/ai/tools/` 目录

使用 Vercel AI SDK 的 `tool` 函数定义四个基础工具：

1. **`rag_search`** — 知识库检索
   - 参数：`query: string`
   - 调用 `hybridSearch`，返回相关文档片段

2. **`search_notes`** — 搜索笔记
   - 参数：`query: string, category?: NoteCategory`
   - 调用笔记搜索 API，返回匹配的笔记列表

3. **`create_note`** — 创建笔记
   - 参数：`title: string, content: string, category?: NoteCategory, tags?: string[]`
   - 调用 Prisma 创建笔记，返回创建结果

4. **`get_time`** — 当前时间
   - 无参数，返回当前日期时间

#### 19.2 Agent 对话 API

**新增文件：** `src/app/api/agent-chat/route.ts`

- 使用 `streamText` + `tools` 参数（Vercel AI SDK 的 tool calling）
- 系统 prompt 描述 Agent 的角色和能力
- Agent 可以自主决定是否调用工具、调用哪个工具
- 保留流式输出和会话管理

#### 19.3 前端集成

**方案选择：**
- **方案 A**：在现有对话页面添加"模式切换"（普通对话 / Agent 模式）
- **方案 B（推荐）**：新建独立的 Agent 对话入口

## 4. P3 阶段 — 体验优化（按需实施）

### 间隔重复回顾

AI 根据笔记内容和用户的浏览频率，定期生成"复习摘要卡片"。用户可以在 Dashboard 中看到"今日复习"模块，包含 3-5 张 AI 生成的知识卡片，支持"已掌握/需复习"标记。

### 文档切片可视化优化

在现有切片查看基础上，增加切片间的 overlap 关系可视化（高亮重叠部分）、切片的 embedding 向量相似度热力图（展示切片间的语义关系）。

### 批量操作支持

笔记列表和知识库文档列表支持多选操作：批量删除、批量导出（笔记导出为 ZIP 包含多个 .md 文件，知识库文档批量下载原始文件）。

### 弱网降级

- Service Worker 缓存策略：对 API 响应做本地缓存，离线时可查看笔记列表和最近浏览的笔记内容
- 请求重试机制：网络请求失败时自动重试（最多 3 次，指数退避）
- 离线指示器：顶部显示"网络连接不稳定"横幅
- 乐观更新：创建/编辑操作先更新本地状态，失败时回滚并提示
